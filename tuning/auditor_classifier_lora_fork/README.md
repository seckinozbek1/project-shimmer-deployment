# Classifier-specific adapter fork: local preparation

This supersedes the fresh zero-B proposal without modifying its sealed evidence. `experiment.json` is the operative design; `seal.json` binds its tested source commit. READY means local preparation criteria pass, not measured GPU function parity or cloud authorization.

`classifier_adapter_init/` contains an isolated byte-for-byte copy of historical step120. The weight binary is local-only and ignored by Git; `adapter_copy.json` binds all 448 tensor byte ranges and full-file hashes. Recreate it with `python tools/prepare_auditor_classifier_lora_fork.py`. This parses headers and hashes tensor bytes without tensor deserialization or model loading. The only numeric weight artifact deserialized locally is the explicitly requested saved linear head, for cached-feature arithmetic.

The copied config retains `inference_mode=true` byte-for-byte. A future loader loads two named slots, `historical_reference` and `classifier_fork`, without changing source config files. Both are frozen during deterministic eval/inference-mode preflight, disabling dropout. `remote_preflight` validates loaded adapter/head/normalization values against bound artifacts, compares 16 TRAIN controls under each slot, deletes the reference, and checks all 1,792 TRAIN predictions, saved metrics and CE. Candidate/head trainability is enabled only afterward. Create the optimizer through returned `Preflight.optimizer`, which rechecks that only candidate LoRA and head are trainable and admits the unchanged `HealthGate` only after successful preflight. No stacked adapter path is allowed.

Use `runtime_bindings.json`, `adapter_copy.json`, `update0_controls.json` and `train_baseline.json` as sealed inputs to the preflight. Hash-check runtime files before model loading as well. The future loader must enforce the existing pinned base revision/weight hash and preparation; this package adds no loader or cloud controller. Reference source files have no writer in this implementation; source hashes are checked at creation, runtime entry and immediately before reference deletion. Optimizer parameter identities exclude every historical reference parameter.

All existing numerical telemetry, update20 admission, schedule, checkpoints and quality gates are imported unchanged from `auditor_classifier_lora_stable.py`. Persist its telemetry callback durably in the future runner. No DEV at update20, no retry. The historical V2 dataset verdict remains NOT_READY and HOLDOUT is unconsumed.

Tests: `python -m unittest discover -s tools -p test_auditor_classifier_lora_stable.py` and `python -m unittest discover -s tools -p test_auditor_classifier_lora_fork.py`. Actual Torch/PEFT hooks are not executed by these no-model tests. A future authorized cloud controller still needs payload, budget and cleanup integration; this local readiness decision supplies no cloud authorization.
