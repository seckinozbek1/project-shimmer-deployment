# Changelog

One entry per product version, in plain English. The version number lives in `VERSION` until the Python package carries it. A version ending in `.devN` is a development snapshot; `rcN` is a release candidate.

## 0.1.0.dev7 (S10, fresh-clone test)

- **A draft under the local profile no longer calls the Claude API.** The draft memo goes through the drafter's own backend (INC-031); gate check 312. Local Draft makes no provider call; it is not yet proven end to end.
- **`shimmer.sh` accepts the venv it makes under Git Bash.** The venv's Python is passed relative to the launcher's folder, which a Windows Python can open (INC-030); check 308 runs it with a real Windows venv.
- **The chat window says what it checked.** Its startup line says the local model is configured and loads on the first request, and a request the model could not answer says the model was not used and why; check 310.
- **The image ships `VERSION` and restores the shipping-gate line** check 252 looks for (open item 7); `seals/` is kept out of the build context; checks that need files the image lacks skip and say which.
- **The 35 frozen launchers moved to `archive/frozen_launchers/`** (open item 20).
- **The README is rewritten for v1** (S11, documents only) and links the results page (`docs/RESULTS.md`). It says what Shimmer is (established mechanisms put together), what it does and does not do, what has been measured (development, exposed, with what the figures do not show), the limitations, a measured hardware and cost summary, install from source and the container image, quickstart, configuration, the constitution and agents, the testing rules and how to reproduce the evaluation. It states that the privacy layer today refuses sensitive runs and does not mask, that switching masking on needs its own amendment, and that the server's one shared token makes Shimmer a single-operator system. The sealed evaluation comes after v1; no package release is promised.
- `CLAUDE.md` narrows "domain-agnostic" to what the evidence supports. Links to README sections that moved now point to `docs/RUNTIME_REFERENCE.md`; the dated history and state documents get dated notes instead of rewrites.

## 0.1.0.dev6 (S7 close, 1 November 2026)

- **The console shows what the pipeline records.** New read-only views for a run's saved model replies and their outcomes (metadata only, never the reply text), the findings a model wrote with their mark in both languages, multi-round runs and their reuse record, the agent switches (INST_FINDER on or off, and why FACT_CHECKER is withheld), the run report and cost rows, and the test-change request log.
- **A sealed test's per-flaw results never reach the console.** Every new view shows a sealed run as counts and timings only; a sealed run's per-flaw routes answer 403 and `POST /evidence` refuses it.
- **Only `/health` and `/console` answer without the token**; FastAPI's own `/docs`, `/redoc` and `/openapi.json` are switched off.
- **The launchers work on Windows again.** `shimmer.bat` lost the quotes of one `for /f` line inside `cmd /c` and stopped before installing anything; fixed. The three launchers reach their menus, end cleanly at end of input, and `SHIMMER_SKIP_INSTALL` skips the install step.
- **The chat window no longer hangs after an error**, and a bare `draft` asks for its topic instead of drafting a memo about the word "draft".
- **A third sealed run arm, L, runs the launcher menu once on a cloud instance** (a review, then a draft) from a sealed list of prompts and answers, with the network denied to its Python children.
- **A refused run no longer shows as a failure.** A multi-round run refused for its declaration (exit 8) and a run refused because `SHIMMER_INST_FINDER=off` has no ratified amendment (exit 9) show as the governance statuses `refused_multi_round` and `refused_inst_finder_unratified`, in the server and the console, in both languages.
- **The launchers' start-up check imports what the menu runs** (`tools/runtime_contract.py --entrypoint launcher`: the readiness check and the intake wizard), not a cloud probe no launcher uses; arm L is sealed only for a workload with no operator redaction rule in force.
- Gate checks 298 to 311 added; check 108 extended to exits 8 and 9.
- **`shimmer.sh` starts from a scripted shell too.** It finds its own folder without `dirname` and adds `/usr/bin` to a PATH that lacks it, so a Git Bash started by a script reaches the menu (open item 54).
- **The console's sealed pages say exactly what they withhold.** The sealed note names the document, file and target names it withholds and that the FACT_CHECKER reasons are shown under Agent switches, sits directly under the multi-round heading, and one model-written finding reads in the singular; the console fixture's records agree with each other, and ten sealed screenshots are re-rendered (open item 55).
- **Checks that prove what they say.** Check 306 now proves the sealed note's wording on its own, refuses a hidden-start flag that Windows would ignore and sees more ways a process can start; check 298 compares the console fixture's records call by call in both directions; check 308 covers an empty PATH; check 311 runs the launcher's opening lines instead of matching one literal line; and check 32 removes the input folders it creates, so a gate leaves the tree as it found it.

## 0.1.0.dev5 (2026-11-01)

- **Development runs on a cloud GPU, end to end.** A sealed bundle now carries the B3 pipeline arm and the B1 bare-model arm, runs several bundles in one instance session (`--batch`), and keeps every entry's evidence even past the soft budget. Each launch is a loop launch: a ledger line before the request, a budget guard, a reaper that ends an instance at its deadline, and up to two loop instances at once, with a third refused.
- **Model output is shaped by its own contract while it is written.** The compact producer and the envelopes of VERIFIER, PRACTICE_AUDITOR and ARCHIVIST decode under a constraint built from each call's own contract (`scripts/contract_decoding.py`); a token the model would have chosen anyway is never changed, the validators are unchanged, and replays on the A10 left every valid reply byte for byte as it was (EDITOR_CLERK's envelope, added at the S5 close, was proven on saved replies and then held on the model in 5 of 5 entries of L12c).
- **VERIFIER is shown no runtime identifiers and may write 4,096 tokens** (FACT_CHECKER keeps 2,048). Both were measured: the largest VERIFIER prompts fell by about half, and at 4,096 most lists that were cut off now end.
- **Multi-round cases are computed in Python**, with no model call for the case records, and a multi-round run is judged by its own evidence and saves its own step times.
- **Benchmark scoring has two labelled readings** (`--scoring benchmark|as_shipped`), the repository scorer reads refusal kinds and multi-round keys, and FinDVer filings are read in segments with a revised bare-model prompt. A CUAD claim-check adapter is added as a secondary arm.
- **A dating fix for four-digit years on Linux, EDITOR_CLERK decoding under its own envelope, and over-bound gathers run as waves.**
- **A request-ledger check** (`tools/loop/request_ledger_check.py`) holds the loop's records against its specification.
- Gate checks 285 to 297 added; development results, every one exposed, are in the stage report (the v1 results page follows with S11).

## 0.1.0.dev4 (2026-10-28)

- **Adapters for five external benchmarks** (`benchmark/adapters/`: ContractNLI, CUAD, ContraDoc, SciTab, FinDVer), written and labelled by third parties on real documents. Each turns a benchmark item into a test bundle in the published input format, maps Shimmer's run output to the benchmark's label by one written rule, and computes the benchmark's own metric, or the closest honest measure with the reason when Shimmer's output cannot produce it. Standard library only; they run from a copied tree. No benchmark data is committed: it stays in the ignored `external/` folder.
- **Two baseline tools for the evaluation** (`benchmark/baselines/`). `python_only.py` (B2) runs Shimmer's computing layer with no model call and marks every file it writes as an ablation, not a review. `bare_model.py` (B1) sends the same model one fixed, preregistered prompt per item with the same document and rules, saves every reply, and records one typed label per item.
- **A preregistration draft and a benchmark selection** (`docs/benchmarks/PREREGISTRATION.md`, `docs/benchmarks/SELECTION.md`): splits, sampling, measures, comparisons and statistics fixed before any holdout is drawn; sample sizes wait for the development runs.
- **The adapters and baselines now travel to a cloud instance** as named extras of the source archive; their fixtures and checks stay out.
- Gate checks 282 (the baseline arms) and 283 (the adapters) added.

## 0.1.0.dev3 (2026-10-28)

- **A published input format and output format (drafts).** `docs/INPUT_FORMAT.md` tells a test preparer everything needed to write a test bundle: documents and units, conventions and their machine directives, the one rule for applying directives, the reference corpus, the answer key with typed reasons, the clean twin, the perturbation probes and how a multi-round case is declared. `docs/OUTPUT_FORMAT.md` tells a scorer what a run folder holds and what each file means. Both are drafts until the sealed evaluation freezes them; every change to a draft is hashed in `docs/loop/VERSIONS.md`.
- **Seeded synthetic test generators** (`benchmark/generators/`, standard library only, never importing Shimmer) for six document families: result sheets, declarations with arithmetic, financial statements, contract terms across versions, regulation-style provisions (with a long-range layout) and neighbour-dependent stock counts. Each test comes with its clean twin and four perturbation probes, at least ten planted flaws with typed reasons, and keys that state ground truth, not Shimmer's output. Generation checks its own figures before it writes anything.
- **A development suite and a long-range corpus** are regenerated from committed seeds (`benchmark/dev_suite/SEEDS.json`, `benchmark/long_range/SEEDS.json`) into ignored folders. Both are exposed by construction and are for development only.
- **Every refused change record carries a typed `reason_kind`** (for example `possible_rename`, `tie`, `unit_mismatch`) beside its sentence, in the pairing map and in `review_data.json`'s `prior_refusals`, so a scorer reads the kind, never the wording.
- Gate checks 281 (the generators) and 284 (refusal kinds) added.

## 0.1.0.dev2 (2026-10-27)

- **Model findings are marked, never hidden and never promoted.** The markdown deliverables, the run summary and the console mark a finding a model wrote as "Written by a model. Not promoted to an amendment. Not checked by Python." `review_data.json` lists them apart under `model_findings_not_promoted`, without a confidence or verdict field, and `GET /runs/{run_id}/findings` says who wrote each record (`written_by`). Only Python's records enter the comparison with an earlier version and its band list. The sentence naming who produced the findings is generated from what actually ran.
- **Amendments read as plain English and sit at their unit's own passage.** One sentence names the unit, the rule, both figures with their units and the relation (a sum names what it added); the rule is quoted; a model's sentence comes last, labelled. A unit Python cannot place sits at document level, cites no other passage, and the comment says so. Rows in the second output language (tr) were added for every new sentence.
- **Reports no longer overstate.** Relations only a model reported are listed apart, in the run summary and in the scorer; `audit_synthesis.md` counts audit-trail patterns, not findings; deliverable headings use colons instead of em dashes. The unused Turkish renderer `run_options.review_markdown` was removed.
- **Multi-round runs review each round in Python and reuse unchanged units.** A later round recomputes only the units whose text, rules, field labels or units of measure changed, records the reuse in `audit/round_reuse.json` and posts the round findings on the run bus. Nothing reads them yet, so no model call is saved. A term renamed with a moved value, or a figure with no unit renamed, is refused as a possible rename, not reported as withdrawn, until a measured rule decides it.
- **The frozen final models accept a declared multi-round Review** (the flag and its case manifest together); Draft and a half-declared request stay refused. The cloud controller admits a multi-round bundle only when it is declared, sealed with a live case manifest and run under `reference_serial`.
- **Every ordinary final launch is a budgeted loop launch.** A new budget guard (`tools/loop_budget_guard.py`) reads the loop ledger and refuses a launch the budget cannot carry or while another loop instance runs; the instance is named `shimmer-loop-...`; launch and termination lines go to the ledger; instance type, rate cap and caps are sealed from the provider inventory and the guard's formula. The general cloud path refuses loop names and ledgers and does not launch while the loop budget is open. No per-run cap is a code default: `budget_deadlines` and the general watchdog take the caps as required arguments and the general path's sealers take them on the command line; the factors of the loop's budget rule (the 1-dollar margin, the 1.5 and 1.3 factors, the type-rule factor 2) and the two reserves (900 and 180 seconds) are code constants. The budget itself is not: the guard and the reaper read it, and the reaper's hard stop, from the ledger's latest `budget_open` or `budget_change` line. A launch with no readable budget line is refused, and the reaper then terminates every loop instance.
- **The controller can run detached, run sealed tests and run batches.** A sealed run prints counts only and writes nothing in the repository except ledger lines; a batch runs B3 and B1 item by item in one session; every run gets a `RUN_REPORT.md` with the Annex A 11.12 fields. The asset-copy declaration must name the bundle's own archive. The sealer refuses an unratified `SHIMMER_INST_FINDER=off`.
- **Every bundle sealed before this version must be sealed again**: six controller files it is bound to changed, so it refuses with "Controller source changed".
- **S2 checker round 2.** Every paired judging call is recorded with its outcome and the deliverables say how many notes were kept; a Word comment's author follows the amendment's provenance (Python for a computed finding); one figure formatter everywhere; an absence is counted apart from computed figures; the run summary's absence section reads as plain sentences; escalations naming unregistered agents are set apart; an unstamped record is never Python's. The cloud sealer keeps binary test files byte for byte; a batch entry already launched is refused; a sealed bundle inside the repository and a `--frozen-tag` that is not a tag are refused; the per-run cap ceiling is the ledger's hard stop; an intent that created no instance stops accruing at its deadline and the reaper closes it; a held ledger lock is reported with its age and process; the run purpose is checked before any provider call.
- Gate checks 278 and 279 added and check 185 replaced; a mocked end-to-end proof of a multi-round launch added (`tools/multi_round_launch_checks.py`).

## 0.1.0.dev1 (2026-10-27)

- **Every model reply is saved.** Each model call writes one record into the run's `audit/model_replies/` folder (the reply, the exact payload, the model and decoding settings), with what became of the reply in `outcomes.jsonl`. With redaction on, only hashes and lengths are kept. The records are never committed.
- **INST_FINDER can be switched off, but only after the operator ratifies it.** `SHIMMER_INST_FINDER=off` takes effect only under an approved constitution amendment; until then a run with it refuses to start. The amendment is drafted, not ratified.
- **The cloud controller no longer contains a credential path.** It finds the credential file through the project's existing lookup, at the moment of use. Bundles sealed before this change must be sealed again.
- **The secret guard refuses seal manifests and saved replies** staged for a commit, by path or inside a staged archive (`scripts/guard_secrets.py --staged`).
- The external collaborator's project name was removed from the two files that held it (it remains in git history until the planned history rewrite).
- New records: a log of proposed test changes, a personal-path inventory for the history rewrite, and a multi-round readiness report.
- Gate checks 275 to 277 added; a pre-existing failure of check 112 fixed.
