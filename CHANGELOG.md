# Changelog

One entry per product version, in plain English. The version number lives in `VERSION` until the Python package carries it. A version ending in `.devN` is a development snapshot; `rcN` is a release candidate.

## Unreleased (after v1)

- **`requirements.txt` pins transformers 4.51.3, not 4.52.3**: the version the laptop and the cloud runtime lock already run, and the one `config/final_models.json` records. A container built from `requirements.txt` now installs 4.51.3, so an image built before this carries 4.52.3 and differs from one built after. The gate on a rented machine (arm G) could not be sealed before this change: its sealer requires every pin to be in the runtime lock. It now also reads a lock's CUDA build label as the same version (`2.5.1+cu121` holds the pin `2.5.1`), and nothing else is loosened.

- **No limit on the number of loop instances** (D-S95, D-382): the guard no longer refuses a launch while another loop instance runs, which the 0.1.0.dev2 entry below describes. Each instance's cap and an overrun reserve are counted within the total budget instead. Every launch still runs on the A10 until a faster machine type has its reference pair measured.

- **A nineteenth agent, JUDGE** (constitution amendment INFRA-049, approved by the operator on 2026-11-08): it answers one narrow question with fixed choices (whether the cells Python selected meet a rule's claim, whether two passages contradict) from its own answer probabilities, writes no text, and runs on `local_auditor` with its own model, Phi-4 (`unsloth/phi-4-bnb-4bit`), under both profiles. Python selects its evidence and runs its declared tools; its answers are model records, never amendments. No shipped rule declares a judge task yet, so no run has reached it. Gate check 331.
- **A rule can now state a claim to compare with a table** (constitution amendment INFRA-048, approved by the operator on 2026-11-07, D-281): under `[compare: cells]` Python selects the table cells that bear on the rule's claim and a local model decides it from its own answer probabilities. A settled "not met" is the new relation `claim_not_met`: a model's record, marked, showing the claim and the cells, and never an amendment. It needs a measured threshold, and none is measured yet. Gate check 326 added.
- **The adapters' `--scoring as_shipped` is now `--scoring v2_primary`** (issue #134, D-269): it reproduces preregistration version 2's primary reading, while the as-shipped figure is sensitivity S-8. The old name is refused on the command line. No reading or number changed.
- **A model can now report a contradiction in words** (constitution amendment INFRA-046, approved by the operator on 2026-11-05, D-264): the Finding record gains the relation `contradiction` and the field `quote_b`. Both passages must be quoted from the unit, and only the two judged paths keep it, after Python's checks; from any other agent it is not a finding. Python checks the words and not the claim, and the record stays a model's, marked and never promoted. No scoring rule changed, though a kept contradiction decides its item like any model record. Check 322 holds it.
- **A model's malformed reply no longer stops a run** (open item 80): a declared field of the wrong shape is removed and named, on every envelope read and on the judged paths; the saved reply stays whole.
- **The document's summaries now count the model findings the master lists** (open item 80), from every finding agent, and say so in both languages.
- **An amendment states its rule's severity** (open item 25), the multi-round records name Python as their writer (open item 45), a date label keeps its own line's word order and a UTF-8 byte-order mark loses no rule (open item 16), and the band record agrees with the finding below the band (open item 22).
- Gate check 323 added.
- **A development scoring that measures detection** (Annex D D-S26 item 1; its rule is decision D-194, written before any score was read with it). The benchmark adapters take `label --scoring detection_dev`: a label rests on a claim the run kept, and an item with no kept claim is reported apart as silence and is never counted as a detection; CUAD's "in at least one passage" rules are read per document, so one passage's absence no longer makes the document's; ContractNLI's "not mentioned" is reached from B3's records when every passage is recorded as not settling the hypothesis. One shared helper (`benchmark/adapters/common/detection.py`) serves ContractNLI, CUAD, ContraDoc and SciTab; the preregistration's two modes are unchanged, and gate check 317 holds the new mode; its proofs fail under each of these neutralisations: silence given its as-shipped label (in the primary and so in S-6 and S-7), S-8 silence rows given their as-shipped class, S-8 rows carrying the primary row's as-shipped fields, CUAD absent from one unit's absence, the not-mentioned reading removed, ContraDoc not contradictory from one unit that holds, the paired-view refusal removed, the counts read as as-shipped again, and the development-only refusal removed (D-195). No saved run has been re-scored with it yet.
- **Python computes four more kinds of flaw** (constitution amendment INFRA-045, approved by the operator on 2026-10-31 and applied by the loop under Annex D D-S19 item 1, D-197; from the parallel track's PATCH_1 v2). The Finding record gains `rate_mismatch` (a figure that is not the stated percentage of another, or a percentage that is not one figure's share of another), `unit_mismatch` (a stated total, or a figure a band applies to, written in another measure, converted only by a decimal prefix declared in `config/unit_conversions.json`), `copy_mismatch` (a table row that does not carry the figure of the unit it names) and `carry_mismatch` (a first row that does not carry the column sum of the unit before). A rate, copy or carry is computed only where a rule names its figures by the unit's own labels. Each is posted as Python's record and becomes an amendment like every computed finding. A comparison Python cannot decide is refused and listed under `relation_refusals` in the pairing map. The console and the Turkish catalog have a sentence for each. After the fresh review (D-198): a rate whose figures also fit another plain reading, or whose whole is zero, is refused; a prefix converts only before a base `config/unit_conversions.json` declares; an unconvertible figure a band rule names is refused on the record; a unit mismatch belongs to the rule whose declared scope or requirement names its figure or measure, or is refused; an agreeing rate, copy or carry no longer drops the rule's other questions; a copy's sources are signed in a multi-round run whatever the copy's outcome; the scorer reads a run made before INFRA-045 as its record read it; `tools/loop/amend_pinned_baselines.py` takes the entry's date.
- **The scorer can hand back its scoring as data** (`tools/score_corpus.py`, `score(..., result=...)`); its printed report is unchanged.
- **A loss table for many scored runs** (`tools/miss_diagnosis.py`). It scores each (run, answer key) pair through the scorer, puts every expected finding lost into one loss class with a sub-cause read from the saved files, and names the code lines that decide it. It reads a run folder, a cloud session or a collected evidence archive, and never opens a key itself. An adapter item whose gold marks no part of the document (a property of the whole document) is read over every part of that document, and the weakest part decides its class; an item whose evidence was cut, or matched no part, is named apart and never read as whole-document. Limit: an item that marks no location carries no cut mark of its own, so a cut that removed its evidence is seen only when another item of the same key is marked beyond the cut, and never on a benchmark whose items mark no location (CUAD and SciTab today). An answer Python refused on a pair where it could compute nothing is named apart, read from the call that refused it.
- `scripts/fn_evidence.py` now reads the pairing map's undecided rules, which it used to report as absent.
- Gate checks 318 (the loss table) and 319 (the four relations) added; checks 179 and 293 follow the longer relation list.
- **`reviewed_document.md` is now the reviewed document itself** (open item 19, part 2; from the parallel track's PATCH_2 v2, applied under D-S26 item 3). It holds the document's own text, whole and in order. Under each part it quotes what concerns that part: each amendment, each of Python's other findings, each model finding (marked "Written by a model. Not promoted to an amendment. Not checked by Python."), each answer Python refused and each rule left unchecked. A header says what was asked, how many of each kind there are and what was not checked. Its counts match their sources: amendments and model findings `review_data.json`, Python's findings the document summary, refusals and unchecked rules the pairing map. The file only renders; it decides nothing. Turkish rows were added for every new sentence.
- **Each agent's raw reply moved to `agent_record.md`.** This is the technical record the old `reviewed_document.md` held: the replies, the judging calls, every registered agent's state and the editorial board's notes. Runs written before this change have that record under the old name and no `agent_record.md`.
- The operative and grounding summaries no longer cut a model's sentence, a rule's words or a cited passage at 240 characters; a passage only a shortened copy of which is on record is said to be not shown.
- Under an active sensitivity layer (off as shipped) the reviewed document is rendered again from scrubbed inputs, so a redacted span, in any form the matcher reads, is gone from the document text and the findings before it is written; a number left in a record is not scrubbed. Every document that reaches the scrub is scrubbed with every span proposed in the run; a document held at the redactor is scrubbed with the spans that are known, and what its redactor would have marked is reported as unknown. A unit id carrying a span is derived again from the scrubbed text; a figure's written forms are read too, and one a renderer writes from a number blocks the document, in the files rendered from the master; `memo.md` ships as the redaction scrubbed it, where it did; a model no longer chooses a span's replacement; the matcher reads a span with or without the configured Arabic article and vowel marks, in either Unicode form and across invisible characters, and no longer slows down on repetitive text.
- Gate check 320 added (the reviewed document); checks 46, 47 and 278 follow the new file.
- **A model's answer Python has nothing to check against is refused on both judged paths** (R1, loop decision D-S22 item 1 (d), from the parallel track's finding). On a judged absence and on a plan Python could compute nothing for, `paired_review.judged_item_refusal` now also refuses an answer with an absence relation and no quote, an answer with a relation that compares two figures and no figure, and an answer with an earlier-version relation when the run declared no earlier version. Which relations are which is read from the Finding record's declared lists (`finding_record.figure_relations()` is the declared relations less the absence and earlier-version ones). Each refusal has its own reason in the pairing map's `absence_refused` or `uncomputable_refused`; refusals made before keep their reasons. `tools/judged_rescreen.py` re-screens the answers a saved run kept, by item id only. Gate check 322 added; the pinned baselines record the change to `_paired_convention_review` and `phase_5_5_convention_review`.
- **Document-level judging for one development experiment, G1** (`benchmark/baselines/doc_judge.py`, approved by the operator on 2026-11-01). Each rule is asked once over the whole document, in the rule's own words, with a short neutral prompt and three outcomes (holds, not met, cannot be settled). A holds or not met is kept only when its quote is found in the document. The run uses the cloud runner's existing replay pass, so no bound controller file changed and no sealed bundle has to be sealed again. The answers are labelled by the benchmark adapters' own rules and scored only through the scorer, with silence counted apart.

A pass is a pilot go, never a claim of doing better than B1.

## 0.1.0.dev2 (2026-10-27)

- **Model findings are marked, never hidden and never promoted.** The markdown deliverables, the run summary and the console mark a finding a model wrote as "Written by a model. Not promoted to an amendment. Not checked by Python." `review_data.json` lists them apart under `model_findings_not_promoted`, without a confidence or verdict field, and `GET /runs/{run_id}/findings` says who wrote each record (`written_by`). Only Python's records enter the comparison with an earlier version and its band list. The sentence naming who produced the findings is generated from what actually ran.
- **Amendments read as plain English and sit at their unit's own passage.** One sentence names the unit, the rule, both figures with their units and the relation (a sum names what it added); the rule is quoted; a model's sentence comes last, labelled. A unit Python cannot place sits at document level, cites no other passage, and the comment says so. Rows in the second output language (tr) were added for every new sentence.
- **Reports no longer overstate.** Relations only a model reported are listed apart, in the run summary and in the scorer; `audit_synthesis.md` counts audit-trail patterns, not findings; deliverable headings use colons instead of em dashes. The unused Turkish renderer `run_options.review_markdown` was removed.
- **Multi-round runs review each round in Python and reuse unchanged units.** A later round recomputes only the units whose text, rules, field labels or units of measure changed, records the reuse in `audit/round_reuse.json` and posts the round findings on the run bus. Nothing reads them yet, so no model call is saved. A term renamed with a moved value, or a figure with no unit renamed, is refused as a possible rename, not reported as withdrawn, until a measured rule decides it.
- **The frozen final models accept a declared multi-round Review** (the flag and its case manifest together); Draft and a half-declared request stay refused. The cloud controller admits a multi-round bundle only when it is declared, sealed with a live case manifest and run under `reference_serial`.
- **Every ordinary final launch is a budgeted loop launch.** A new budget guard (`tools/loop_budget_guard.py`) reads the loop ledger and refuses a launch the budget cannot carry or while another loop instance runs; the instance is named `shimmer-loop-...`; launch and termination lines go to the ledger; instance type, rate cap and caps are sealed from the provider inventory and the guard's formula. The general cloud path refuses loop names and ledgers and does not launch while the loop budget is open. No per-run cap is a code default: `budget_deadlines` and the general watchdog take the caps as required arguments and the general path's sealers take them on the command line; the factors of the loop's budget rule (the 1-dollar margin, the 1.5 and 1.3 factors, the type-rule factor 2) and the two reserves (900 and 180 seconds) are code constants. The budget itself is not: the guard and the reaper read it, and the reaper's hard stop, from the ledger's latest `budget_open` or `budget_change` line. A launch with no readable budget line is refused, and the reaper then terminates every loop instance.
- **The controller can run detached, run sealed tests and run batches.** A sealed run prints counts only and writes nothing in the repository except ledger lines; a batch runs B3 and B1 item by item in one session; every run gets a `RUN_REPORT.md` with the Annex A 11.12 fields. The asset-copy declaration must name the bundle's own archive. The sealer refuses an unratified `SHIMMER_INST_FINDER=off`.
- **Every bundle sealed before this version must be sealed again**: six controller files it is bound to changed, so it refuses with "Controller source changed".
- **S2 checker round 2.** Every paired judging call is recorded with its outcome and the deliverables say how many notes were kept; a Word comment's author follows the amendment's provenance (Python for a computed finding); one figure formatter everywhere; an absence is counted apart from computed figures; the run summary's absence section reads as plain sentences; escalations naming unregistered agents are set apart; an unstamped record is never Python's. The cloud sealer keeps binary test files byte for byte; a batch entry already launched is refused; a sealed bundle inside the repository and a `--frozen-tag` that is not a tag are refused; the per-run cap ceiling is the ledger's hard stop; an intent that created no instance stops accruing at its deadline and the reaper closes it; a held ledger lock is reported with its age and process; the run purpose is checked before any provider call.
- Gate checks 278 and 279 added and check 185 replaced; a mocked end-to-end proof of a multi-round launch added (`tools/multi_round_launch_checks.py`).

## 0.1.0.dev1 (2026-10-27)

- **Every model reply is saved.** Each model call writes one record into the run's `audit/model_replies/` folder (the reply, the exact payload, the model and decoding settings), with what became of the reply in `outcomes.jsonl`. With redaction on, only hashes and lengths are kept. The records are never committed.
- **INST_FINDER can be switched off, but only after the operator ratifies it.** `SHIMMER_INST_FINDER=off` takes effect only under an approved constitution amendment; until then a run with it refuses to start. The amendment is drafted, not ratified.
- **The cloud controller no longer contains a credential path.** It finds the credential file through the project's existing lookup, at the moment of use. Bundles sealed before this change must be sealed again.
- **The secret guard refuses seal manifests and saved replies** staged for a commit, by path or inside a staged archive (`scripts/guard_secrets.py --staged`).
- The external collaborator's project name was removed from the two files that held it (it remains in git history until the planned history rewrite).
- New records: a log of proposed test changes, a personal-path inventory for the history rewrite, and a multi-round readiness report.
- Gate checks 275 to 277 added; a pre-existing failure of check 112 fixed.
