# producer-semantic-policy-v1

Prospective policy for producer-coverage-amendment-v1; renderer producer-target-renderer-v1.
Derived solely from compact producer contract, semantic-task-v1 record schema and generic task semantics. No amendment target packet or legacy authored target was inspected to design this policy. Existing conversation reports describe historical limitations; they are not fresh reviewer inputs or answers.

## Ownership and claims
Python owns exact source, offsets, order, document/paragraph identity, reconstruction and provenance. A producer returns one semantic item per owned alias in routing order. Context is not owned. Every explicit CLM-* assertion ID in an owned span is retained, including contradictory assertions. Do not reconcile conflicting assertions. A contradiction does not itself create epistemic uncertainty; only explicitly expressed lack of knowledge, uncertain interpretation/state or qualifying epistemic language licenses uncertainty. No new production wire field is introduced. Refusal is appropriate only for genuinely incomplete/unusable source, not mere uncertain content. An examined span with no claims, gaps or uncertainty is empty.

## Typed atoms
Each gap/uncertainty atom has exactly: kind, category, subject, attribute, relation, scope, unit, span, refs, origin, support. Optional wording is nonsemantic. Support is a nonempty exact substring of the owned source establishing the annotation; it is evidence for the review, not training target prose. Semantic identity excludes support/wording but includes every other field. Atom refs equal all refs explicitly supplied in that owned span. Required packet refs remain preserved across items. No context-only/invented refs. Claims are exact IDs; item refs are exact owned refs.

kind: gap or uncertainty.
Gap category: missing_information for explicit absent information or an unanswered explicit question; explicit_question for an explicit question whose answer is supplied. Preserve explicit surface questions even in question-answer layouts, per the existing contract. Do not infer a gap from mere silence.
Uncertainty category: unknown (including explicitly uncertain/unresolved interpretation/state). Other epistemic categories are not automatically admitted; use review_ambiguity for unsupported distinctions requiring policy extension. Conflicting assertions alone are never an unknown atom.
subject: owned_record by default; entry:1 / entry:2 etc. for explicit ordinal entry referents; amendment for an explicit amendment state/time; entity:<normalized name> when needed for another explicit referent. Do not collapse different referents.
attribute: reporting_date, recording_date, observation_date, effective_time, recorder, interpretation, ratification_status, entry_content, entry_order, quantity, identity, or state. These are domain-agnostic semantic attributes, not benchmark sentence matches. Preserve ambiguity rather than guessing a different attribute.
relation: null normally; first, next, before, after for explicit event/order inquiries. Distinct relation/state/unit/subject/alias/refs remain distinct. scope: owned_record unless an explicit scope qualifier is necessary; normalize that qualifier with lowercase snake_case. unit: null or the explicit unit. origin: source_explicit only.
Use reporting_date only for report/reporting date, observation_date for observation, recording_date for recording or unqualified record date. Missing ratification status is a gap; unclear whether ratified is unknown ratification_status. Interpretation of a specified ordinal entry uses that entry as subject. General interpretation uses owned_record.

## Canonical rendering
All material atoms are normalized deterministically. A finite attribute alias map allows reporting date/date of report, recorded date/recording date, status of ratification/ratification status, and who recorded/recorder. No fuzzy matching, embeddings, post-gold additions or packet-specific strings.
Canonical gap wording: `Missing information: {subject}; {attribute}; {relation}; {scope}; {unit}.` for missing_information, and `Explicit question: ...` for answered questions. Canonical uncertainty wording: `Explicit unknown: ...`. The literal `none` represents absent relation/unit. Claims/refs and atoms sort deterministically, duplicates reject. Existing production items fields only: span, claims, questions, uncertainty, status, refs. Refusal stays {items:[],status:refused}. No source prose reconstruction in output.

## Source evidence and review ambiguity
Each support quote must be an exact substring of the owned span. Gap support must show an interrogative or explicit missing/unavailable/not-supplied/absent/unnamed condition. Uncertainty support must include an explicit epistemic cue (uncertain, unclear, unknown, unresolved, undetermined, not known). Contradiction/conflict alone is insufficient. Completeness and referent correctness remain substantive blind-review obligations; deterministic cue validation is a guard, not a general semantic oracle. source_uncertainty_present equals presence of uncertainty atoms. review_ambiguity means annotator uncertainty about the label, never mere source uncertainty.

## Legacy comparison and decision policy (prospective)
Freeze and commit all fresh labels and canonical targets before reading legacy gold. Compare claim/ref/refusal exactly. Project legacy free wording only by the frozen generic attribute/referent/question grammar; unknown wording is a projection limitation, not automatic semantic error. Canonical strings are invertible. Source-explicit sequence questions and all explicit epistemic qualifiers are required under this policy; legacy omissions can be classified under-specification only with exact source evidence and unanimous fresh semantics or valid adjudication. A source-contradiction-only uncertainty is an error under this policy. Unsupported machine atoms are machine errors. Different grounded meanings that cannot be resolved deterministically remain real semantic disputes/unresolved and ineligible. Mere unsupported legacy wording may be resolved only when its source-bound semantics map uniquely to an existing machine atom with the same attribute/referent; no after-the-fact synonyms.
