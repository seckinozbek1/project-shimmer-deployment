**Lane agents.** Each lane worktree is made by the lead with `git worktree add -b lane/s01-<name> .claude/worktrees/s01-<name> loop/s01` (D-004; spec IV.5's own fallback). The spec says lane agents commit on their lane branch (line 542). Before the first lane agent starts, one subagent proves it can write and commit inside such a worktree, because S0 measured that subagents cannot write into the session scratchpad. If it cannot, a Class R decision is recorded in `DECISIONS.md` before the lead does that lane's work itself in the worktree. Every lane agent and the Part 2 and Part 6 research subagents run as unnamed subagents (no `name` on the Agent call, so none becomes a teammate), on Opus at high effort (the session's `CLAUDE_CODE_EFFORT_LEVEL=high` applies; no smaller model is ever set).

## Per-commit procedure (IV.7)

Stage named paths only. `git check-ignore -v` on every new file. Scan `git diff --cached` for key patterns; from C1 on, also run the new staged-path logic of `scripts/guard_secrets.py`. Check added lines for em dashes and run the H5 pattern and the three private patterns over the staged files (counts only; labelled "incomplete: private patterns missing from `.claude/` (I.0 item 4 failed); the same three patterns were applied from `docs/loop/private/loop_private_patterns.txt`", D-002). Commit with the attribution lines. Run the full gate on that commit: the main gate plus the six side gates (`tools/ordinary_final_controller_gate.py` with `--output-dir`); restore the tracked log the final-integration side gate rewrites. Compare with the baseline of its environment (main checkout: PASS 243, WARN 1, SKIP 3, FAIL or ERROR 28, the S0 non-pass set; new checks add PASS rows). The first gate run inside a lane worktree records that environment's baseline in `GATE_BASELINE.md`.
