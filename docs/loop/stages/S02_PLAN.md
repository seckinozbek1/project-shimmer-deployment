### S2c. The run controller (controller lane)
1. External test-bundle path and external output path; the current behaviour (bundle from the repository, output under `docs/fix/`) stays the default for development runs. Design: S1 Part 6 section 3.
2. The run seal includes the manifest hash (11.10.3, B.3).
3. Report template for 11.12: every field 11.12 lists, plus the purpose line and the sealed-or-exposed line (B.1), the `SHIMMER_INST_FINDER` value (closes open item 12's report half), the FACT_CHECKER withholding with its two reasons (B.4), the instance type and price, the role-separation statement for sealed runs (IV.10); a field that does not apply says why. Written by `tools/analyze_ordinary_final_run.py` (which writes `FINAL_STATUS.json`).
4. Budget parameters: instance type, region, rate cap, soft cap and hard cap become execution-manifest fields set at each launch from the live price (`metadata.hourly_rate`) and the IV.3 per-run cap formula; the watchdog's `deadlines()` keeps turning caps into deadlines; the type fallback rule of IV.3 (another type only at no more than twice the A10's last recorded price). Replaces the hard-codes listed in S1 Part 6 section 8 (including `cloud_run_common.budget_deadlines` where the ordinary final path uses it).
5. Loop budget guard: every launch path reads the loop ledger at the path it is given (and, when R runs it, `R_INPUTS.json`), and refuses if the per-run cap formula leaves less than the forecast, or if another loop instance is running. Proof on fixtures with a mocked provider.
6. Ledger path and instance names: launch and termination lines appended to the given ledger path; the instance name always starts `shimmer-loop-` and is written with its deadline before the launch request; ledger lines never carry test content.
7. Runs that survive the session: the controller can run detached and calls `SetThreadExecutionState` (`tools/loop/keep_awake.py`) while an instance runs; proof on fixtures with a mocked provider that killing the parent does not stop the controller, and that the reaper still terminates the instance at its deadline if the controller dies.
8. Sealed mode: never writes the bundle or outputs to `shimmer-filesystem` or any persistent cloud storage; prints counts and timings only (B.8); writes nothing in the repository except ledger lines to the ledger path it is given. Gate check compares the repository tree before and after a fixture sealed run.
9. Protected-test guard (`tools/ordinary_final_run.py` around 61): for sealed runs only, replaced by a check that the run is declared sealed, the bundle hash matches the seal and the code commit matches the frozen tag; exposed runs behave as today.
10. Multi-round in the controller: a declared multi-round run is accepted (S2b items 1 and 2).
11. Batches: several test bundles in one instance session, each with its own run folder, seal entry and report; B3 and B1 on the same items item by item so any stop leaves paired data. Proof on fixtures.
12. New controller phases classified in `tools/ordinary_final_progress.py` (`READERS` or `COMPLETION_ONLY`; check 274).
13. Named extras for the cloud source archive (`tools/prepare_ordinary_final_run.py` around 26 to 29): a list that later stages extend (S4f adds `benchmark/baselines/`, S4c adapter code); a listed path that does not exist fails the archive build with one line; test bundles travel by the external bundle path, never inside the source archive.
14. Asset copy: MATCH only with the operator's `asset_copy_declaration.json` (`operator_authorized: true`) for that bundle; the controller never writes that declaration; MATCH or no MATCH recorded in the run report; with no MATCH the upload is in the forecast (see R8).
15. Controller binding: list the bound files changed in S2 and state that earlier bundles cannot be re-executed with them; new manifests carry the new hashes (see R9 for `scripts/agent_wrapper.py`).
16. Only live controller files change; frozen tools stay as they are.
17. Run the controller side gate and the cloud-run checks with the full gate.
