## Items

### S3a. The published input format
1. `docs/INPUT_FORMAT.md`: everything a test preparer needs and nothing more: documents and how units are labelled; conventions and their syntax; every machine directive (`[scope: ...]`, `[requires: ...]`, severity and subject tags, and any other bracket declaration the parser reads) and what it does; the mandate format for negotiation-style tests; the reference corpus; per-test settings; the answer-key format with typed reasons; the clean twin; how a multi-round case is declared (section written after S2 merges, from S2b's live case manifest). Plain English, zero-base, every term defined where it first appears, small examples not taken from any existing test. Sources: `scripts/convention_parser.py`, `scripts/pairing_map.py`, `scripts/role_resolution.py`, `tools/score_corpus.py`, `corpus_ingest/`, `CLAUDE.md`. Proof: item 4.
2. The one written rule by which directives are applied, independent of any test (for example: every completeness rule declares the fields its text names).
3. Draft now, freeze later: marked `input-format-v1-draft`; its SHA-256 recorded in `docs/loop/VERSIONS.md` each time it changes; frozen as `input-format-v1` at S8a item 2 (blocked this session, D-007), never changed after. Every change to the draft before the freeze, including the changes S3 itself makes (closing item 4's guess points, adding the multi-round section), is followed by: merging `loop/s03` into the generators lane, regenerating the development suite and the long-range corpus, re-running the generator gate checks, re-running the adapter gate checks wherever they exist on the branch (from S4's merge on; never skipped once they exist), and recording the new draft hash.
4. A code-blind checker writes a small test from the document alone and lists every point where it had to guess. The `loop-checker` definition cannot be written this session (D-001); the substitute is a fresh `Plan` checker, whose context was shown at S0 to hold no `CLAUDE.md` text, handed only `docs/INPUT_FORMAT.md` and told to read no other file. Its list of guesses and how each point was closed, with the commit, go into `S03_REPORT.md`.
5. `docs/OUTPUT_FORMAT.md` after S2 merges: what a run folder contains and what each file means, for the scorer (role C); a draft `output-format-v1-draft`, kept current through S5, hash recorded in `VERSIONS.md` on each change, frozen at S8a; from C0's final run until the freeze only additions the scorer does not read (C0 is blocked this session, D-007).

### S3b. Synthetic generators (development), generators lane
6. `benchmark/generators/`: seeded generators writing complete test bundles in the published input format (the current draft): documents, conventions or mandate, reference corpus, per-test settings, answer key with typed reasons, clean twin, perturbation probes. Domain words live in generator templates and generator config under `benchmark/` only, never in `scripts/`, `config/` or `tools/` (check 174). Standard library and `requirements.txt` pins only. Families: (1) tabular result sheets against reference ranges (range violations, missing required fields, totals that do not add up, unit mismatches); (2) declarations or statements with arithmetic (sums, ratios, rates, cross-row checks); (3) financial-statement style (line items, subtotals, totals, period comparisons); (4) contract or terms documents across two or three versions (renamed terms with unchanged values, renamed terms with moved values, withdrawn terms, terms new in a later version, reordered sections, values in a different format), which supplies the synthetic rename probes for S2b item 5 (its multi-round case declaration is written only after S2 merges, against S2b's live case manifest; anything built earlier is regenerated and re-checked once that section lands); (5) regulation-style provisions (cross-references, definitions far from their use, conditions pointing at a field and at another rule); (6) neighbour-dependent flaws: a unit that is only wrong given the unit before or after it.
7. Every generated test: at least 10 planted flaws of mixed kinds (at least three kinds), each with a typed reason in the key (where it is, which rule it breaks, the figures that conflict); clean distractors; a clean twin with every flaw repaired; all four perturbation probes (reworded labels, reordered sections, a term only in the later version, a value in a different format) (11.4). Single-version families (1, 2, 3, 5, 6) meet the "term only in the later version" probe by shipping each test with a second, later version of the document (the earlier version declared as the prior, the way the existing negotiation corpora declare one), in which one term appears for the first time.
8. Self-validation, run by every generator before it writes and asserted again by the gate check: at least 10 flaws and at least three kinds; every flaw has a complete typed reason; at least one clean distractor; a clean twin exists and contains no planted flaw; all four probes present; every planted figure checked arithmetically by code. A generator that fails its own validation writes nothing.
9. File-name traps: no source file name matching `**/*key*`, `**/*config*.py`, `**/*secret*`, `**/*credential*` unless an exact re-include line is added; `git check-ignore -v` on every file meant to be tracked.
10. Gate checks (`scripts/generator_checks.py`, registered by the lead): each family generates a bundle from a fixed seed, its self-validation passes, the same seed gives byte-identical output, a planted flaw removed from the key is caught by the validator; skip (not fail) when `benchmark/generators/` is absent (the container image, T15). Neutralise, fail, restore, pass.
